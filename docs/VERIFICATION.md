# Проверки и границы валидации

## Воспроизведение

После установки зависимостей из README:

```bash
python -m pytest -q
python scripts/verify_examples.py
bash -n scripts/publish_github.sh
```

Тесты используют подменённые ответы LLM API. Проверка примеров сопоставляет
JSON-карточки с `examples/products.json`, проверяет длины SEO-полей,
характеристики, отсутствующие поля и технические утверждения. Она не обращается
к паспорту и не доказывает истинность подготовленных входных данных.
Происхождение параметров описано в [`SOURCES.md`](SOURCES.md).

Для проверки браузерного интерфейса после установки Playwright/Chromium:

```bash
python scripts/build_preview.py
python scripts/check_ui.py
```

Сценарии охватывают импорт и экспорт, ошибки JSON/API, сохранение результата,
отмену ожидания, экранирование, адаптивную вёрстку и reduced motion. Генерация
в браузерных сценариях использует подменённые HTTP-ответы. Скриншоты интерфейса
в `docs/` иллюстрируют редакторские образцы; снимок загрузки сделан с
подменённым ожидающим ответом.

## Реальный LLM API

```bash
python scripts/live_smoke.py
python scripts/verify_examples.py --output-dir output/live
```

Эти команды требуют доступной модели Ollama или действительного ключа
облачного провайдера. Ollama использует ресурсы машины с моделью, облачный
API расходует квоту провайдера.
Скрипт сохраняет ответы двух товаров в `output/live/`, отдельно от ручных
образцов. Повторные попытки могут увеличить число обращений к API. Успех
live-проверки подтверждается только завершённым запуском и сохранёнными
результатами; наличие скрипта или прохождение mock-тестов этого не подтверждает.

## Статус после исправлений

Повторная проверка обновлённого кода и live-запуск ещё не зафиксированы в этом
документе. Предыдущие результаты не используются как подтверждение новых
проверок технических значений. GitHub Actions настроен для Python 3.11 и 3.12;
результат облачного запуска следует проверять после публикации репозитория.

## Ограничения

Валидация формата, технических значений и части рискованных утверждений
не даёт полной смысловой гарантии. Нужны проверка входных данных по источникам
и редакторская проверка каждого черновика (`requires_editor_review: true`).
